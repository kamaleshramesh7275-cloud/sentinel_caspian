01 — Problem Statement

The Incident Response Crisis

Modern cloud-native environments generate overwhelming volumes of alerts, stack traces, and automated notifications. Current tooling fails engineers in four critical, measurable ways.

🔔

Alert Fatigue & Noise Pollution

A single database connection pool exhaustion triggers thousands of downstream HTTP 500 errors — each one firing a separate alert. Engineers become desensitized and miss real outages buried in noise.

Industry stat: 76% of on-call engineers report alert fatigue weekly
⏱️

Prolonged MTTA & MTTR

Human-driven triage requires engineers to manually context-switch between dashboards, decode stack traces, assess blast radius, and coordinate across tools — all while a production system burns.

Average MTTA: 14 minutes. Every minute costs ~$5,600 in enterprise downtime
📡

Cross-Channel Communication Friction

Escalations get lost across fragmented tools — Slack threads, Telegram groups, Email inboxes. Crucial minutes are wasted trying to notify on-call personnel across disconnected systems with no shared state.

23% of SLA breaches occur due to missed notifications across channels
📋

Postmortem Deficit

Once an incident is resolved under stress, postmortem creation is frequently delayed or skipped. Root-cause analyses are lost in ephemeral chat histories. Institutional knowledge evaporates.

60% of postmortems are never written — same incidents repeat
The fundamental problem: Existing tools tell you that something is wrong. They cannot tell you why, how bad, or what to do — and they certainly can't do it autonomously.

04 — Our Innovations

What Makes Sentinel Different

Six architectural and design innovations that no existing tool has combined into a single system.

Innovation 01

🧠 Explainable AI Severity Reasoning

Every severity decision comes with a natural-language justification written by the LLM, stored in the database, rendered in Slack messages, and included in postmortems. Engineers can audit every AI decision ever made.

Others: black-box label Sentinel: auditable reasoning chain
Innovation 02

⚡ Neuro-Symbolic Clustering Override

LLM handles ambiguity. Hard rules handle certainty. When the same error_signature appears 3+ times in a 20-minute sliding window, a programmatic override forces severity escalation — the LLM cannot ignore it.

Others: static rules OR AI Sentinel: rules + AI hybrid
Innovation 03

🔗 Unified Cross-Channel Thread Identity

One incident ID persists across Slack, Telegram, and Email via the Caspian SDK. A reply anywhere collapses the entire escalation chain. No duplicate alerts. No conflicting states across channels.

Others: siloed per channel Sentinel: single incident thread
Innovation 04

💬 Natural Language Intent Parsing

Engineers reply in natural language — "looks like a DB overflow, rolling back" — and Sentinel's Intent Parser Agent classifies intent as ACK/INVESTIGATING/RESOLVED and updates incident state. No slash commands, no app navigation.

Others: /ack INC-4521 required Sentinel: "on it" is enough
Innovation 05

📄 Autonomous GitHub Postmortems

On every resolution, Sentinel synthesizes the full incident timeline — channel messages, escalation history, LLM reasoning, TTR — into a structured Markdown postmortem and commits it directly to GitHub via REST API.

Industry: 60% never written Sentinel: 100% automated
Innovation 06

🎨 Adaptive Message Tone Intelligence

Sentinel knows that a Slack message at your desk needs full technical detail (Block Kit, stack trace, incident ID), a Telegram ping at 3am must be readable in 2 seconds, and an email needs a formal HTML report for compliance.

Others: one format everywhere Sentinel: channel-aware messaging

05 — System Architecture

Multi-Agent AI Pipeline

Three specialist LLM agents, each owning a distinct phase of the incident lifecycle. State flows through a PostgreSQL database. No agent holds state — enabling horizontal scalability.

1

Webhook Ingestion — FastAPI

Receives raw payloads from Sentry, Datadog, GitHub CI, or any custom APM. Payload size: 2KB–50KB. Stored as Event in PostgreSQL with error_signature hash for clustering.

2

Severity Reasoning Agent — LLM Core

Queries last 30 min of events with same signature. Builds cluster_analysis context. Calls GPT-4o-mini (temp=0.2, json_mode) with structured prompt. Returns {severity, reasoning, override_triggered}. Fallback: deterministic cluster-count scoring if LLM unavailable.

3

Caspian CommClient — Unified Channel Dispatch

Routes formatted notifications to Slack (Block Kit technical), Telegram (short urgent), or Email (formal HTML) based on incident severity and escalation rules. SLA thresholds: CRITICAL=2min, HIGH=5min, MEDIUM=15min, LOW=60min.

4

APScheduler — 30-Second SLA Tick

Background job polls every 30 seconds. Identifies unacknowledged incidents past their SLA window. Escalates to next channel in path (Slack→Telegram→Email). Increments escalation_count. Continues until status=ack.

5

Intent Parser Agent — Natural Language ACK

Receives engineer replies via @client.on_message unified handler. Calls GPT-4o-mini (temp=0.1) with message + incident context. Returns {intent, confidence, follow_up_question}. Maps to ack/investigating/resolved/escalate status transitions.

6

Postmortem Agent — GitHub Auto-Commit

Triggered on resolved intent. Aggregates all ThreadContext rows (full cross-channel timeline). Calls GPT-4o-mini (temp=0.3) to generate GitHub-flavored Markdown. Commits via GitHub REST API to postmortems/incident-{id}-{date}.md.
